## 3. 测试策略

### 3.1 测试级别与类型

| 级别 | 对象 | 类型 | 执行方式 |
|---|---|---|---|
| L1 单元测试 | 解析引擎 / 利润引擎 | 功能 + 边界值 + 等价类 | pytest 直调函数 |
| L2 接口测试 | 全部 78 个 API 中的 66 个核心端点 | 功能 + 契约 + 异常 | TestClient（ENV-T） |
| L3 集成测试 | 导入→ODS→DWD→核算→快照→溯源 全链路 | 场景 + 数据一致性 | TestClient + DB 直查（ENV-T） |
| L4 系统测试 | 在线实例 | 冒烟 + 性能采样 + 构建验证 | HTTP 只读（ENV-S）+ npm build |
| L5 安全测试 | 认证/授权/注入 | 渗透样本（ASVS 子集） | TestClient（ENV-T） |

### 3.2 用例设计方法
- **等价类划分**：登录（正确/错误密码/不存在/停用）、文件类型（合法 xlsx/csv / 非法 txt）、数值格式（中/欧/负数）
- **边界值分析**：日期格式全集、quantize 精度 0.01/0.0001、表头定位扫描 15 行、limit 参数边界
- **错误推测**：12 小时制 PM 剥离 bug、德语点分日期、Unicode 减号、括号负数（历史 bug 温床回归）
- **场景法**：导入→锁结→核算→补录→重算→溯源 全业务流
- **独立复算**：绕开管线直接对 ODS 原始行求和，与 fact 表/快照三方交叉比对（项目验收基准方法）

### 3.3 测试优先级
P0（必须全过）：利润公式、导入落库正确性、认证、数据一致性对账
P1（允许 0 Blocker/0 Critical 缺陷）：核算快照、溯源、权限越权、导出
P2（允许 0 Blocker）：看板、管理配置、性能冒烟

### 3.4 准入 / 准出标准

**准入**：代码可启动（/health 返回 LMG-ERP）；测试环境可建库；pytest 环境就绪。

**准出**：
1. P0 用例通过率 100%；总体通过率 ≥ 95%
2. 无未关闭的 Blocker/Critical 缺陷；Major 缺陷有明确的修复计划
3. 数据一致性对账（三方交叉）差异 = 0.00
4. 语句覆盖率：`app/services/profit/`、`app/services/importer/parser.py` ≥ 80%
5. 性能冒烟：关键查询接口 P95 < 3s（测试数据量级）

### 3.5 缺陷等级定义

| 等级 | 定义 | 示例 |
|---|---|---|
| Blocker | 系统不可用/数据损坏/核心公式错误 | net_amazon 复算不一致 |
| Critical | 主要功能失效、安全越权 | 非管理员可见全部店铺数据 |
| Major | 功能缺陷有明显替代路径 | 某导出列缺失 |
| Minor | 轻微问题（提示文案、边界体验） | 报错文案不精确 |
| Suggestion | 改进建议 | — |

## 5. 测试实施说明

### 5.1 执行方式
```bash
cd backend
set DB_NAME=lmg_erp_test            # 隔离测试库（conftest 自动建库/销毁）
python -m pytest tests/ -v --cov=app/services --cov-report=term --junitxml=../docs/test-results/junit.xml
```
- conftest.py：会话级 fixture——建 `lmg_erp_test` 库 → 建表/种子 → 执行 → 销毁库
- 合成报表用 openpyxl 在 `tmp_path` 动态生成（不依赖真实业务报表，可重复执行）
- 全部用例可通过 `pytest -m "not perf"` 排除性能冒烟

### 5.2 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | 共享 MySQL 服务器，误写生产库 | DB_NAME 强制 lmg_erp_test；ENV-S 仅只读请求；测试后销毁测试库 |
