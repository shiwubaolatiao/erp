## 5. 缺陷报告

### DE-01【Critical｜已修复✅】所有 Excel 导出接口 500
- **现象**：生产实例实测 `GET /api/v2/export/costs` 返回 500（测试中 6 个导出用例全部失败）
- **根因**：[export.py](file:///E:/项目/erp重构/backend/app/api/v2/export.py) `_xlsx_response()` 将中文文件名直接写入
  `Content-Disposition` 头，违反 RFC 5987（header 值必须 latin-1 可编码）→ uvicorn/h11 编码失败
- **影响**：导出功能整体不可用（销售/快照/原始行/资金流/缺失SKU/成本）
- **修复**：`filename*=UTF-8''` 后接 `urllib.parse.quote(filename)` 百分号编码
- **回归**：6 个导出用例通过，下载头与二进制完整性验证 OK

### DE-02【Major｜已修复✅】非法 period_month 导致未处理 500
- **现象**：`/query/sales?period_month=not-a-month` 触发 `ValueError: invalid literal for int()`
- **根因**：`_month_range()`（query.py）与 `_month_bounds()`（export.py）直接 `int()` 切片解析，无格式守卫
- **修复**：两处增加 `YYYY-MM` 校验，非法输入返回 400「period_month 格式应为 YYYY-MM」
- **回归**：TC-NEG-006 敌意输入组全部 <500

### DE-03【Major｜已修复✅】汇率修改接口 NameError 500
- **现象**：`PUT /api/v2/admin/exchange-rates/{id}` 返回 500
- **根因**：[products.py](file:///E:/项目/erp重构/backend/app/api/v2/products.py) 处理器引用 `ExchangeRate` 模型但未导入
- **修复**：补全模型导入
- **回归**：TC-ADM-001 汇率 CRUD 全链路通过

### OBS-01【建议｜未修复】线上查询延迟波动大
- 在线实例 `/query/sales` 与 `/dashboard/summary` 热请求中位延迟 2.3s / 2.9s，
  但抖动明显（单次采样最高 6.2s）。测试数据量级下 ENV-T 同接口仅 8.5ms / 25.5ms，
  差异主要来自真实数据量与远程库网络。建议：核查 biz_date/复合索引、评估看板查询缓存与分页策略。

### 设计确认（非缺陷）
- 用户删除为**软删除**（status=disabled），删除后登录返回 403「账号已停用」——与代码设计注释一致，测试预期已按设计修正。
- `/query/sales` 的 `sales_usd` 仅统计 Order 行，Refund 金额单列 `refund_amount`——与实现语义一致，用例已按口径校正。
- 批次含异常行时状态为 `partial`（部分成功）——合理设计，用例已覆盖。

## 9. 遗留风险与建议

1. **性能（OBS-01）**：真实数据量下查询延迟秒级且波动大，上线前建议做索引核查与慢查询治理；本轮未做压力测试（范围外）。
2. **UI 自动化（范围外）**：前端仅验证可构建与可达，建议下一迭代引入 Playwright 冒烟套件。
3. **AI / 广告 Agent**：仅验证接口契约与权限拦截，对话质量与外部 LLM 依赖未测（范围外）。
4. **旧库迁移**：旧数据库不在当前服务器，迁移演练未覆盖（README 已知限制 #3）。
5. **安全深度**：本轮覆盖认证/授权/注入/XSS 样本（ASVS 子集），未做完整渗透测试。
